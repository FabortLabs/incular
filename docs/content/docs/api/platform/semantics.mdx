Desktop accessibility uses AccessKit; screen-reader behavior needs native
validation. Semantics expose logical counts and materialized indices without
one node per logical row.

## Core types

| Type | Purpose |
| --- | --- |
| [`SemanticRole`](/docs/api/platform/semantics) | Button, header, image, link, list, meter, progress, text, … |
| [`SemanticAction`](/docs/api/platform/semantics) | Action kinds + invocation payloads |
| [`SemanticActionKind`](/docs/api/platform/semantics) | Enumerated action vocabulary |
| [`SemanticNodeId`](/docs/api/platform/semantics) | Stable node identity |
| [`SemanticState`](/docs/api/platform/semantics) | Node state snapshot |
| [`SemanticsTree`](/docs/api/platform/semantics) | Whole-tree queries |

Use `OrdinalSortKey` for numeric traversal order or
`Semantics::custom_sort_key(CustomSemanticsSortKey::named(value, "group"))`
for a Rust value with its own ordering. Keys sort only within a consecutive
run of the same type and name. Equal keys keep their previous traversal
order. Traversal order does not change painting or pointer hit testing.

```rust
use incular::prelude::*;
use incular::widgets::{ExcludeSemantics, MergeSemantics};

fn main() {
    let app = Application::new(|_cx| {
        Directionality::new(
            TextDirection::Ltr,
            Container::builder()
                .padding(EdgeInsets::all(24.0))
                .alignment(Alignment::CENTER)
                .child(
                    Column::builder()
                        .main_axis_size(MainAxisSize::Min)
                        .spacing(8.0)
                        .children(Vec::<Widget>::from([
                            Semantics::new(Text::new("Close")).label("Close").into(),
                            MergeSemantics::new(Text::new("Merged")).into(),
                            ExcludeSemantics::new(Text::new("Art")).into(),
                        ]))
                        .build(),
                )
                .build(),
        )
        .into()
    })
    .expect("valid application");
    incular::run(app).expect("run application");
}
```

## Widgets

`label` names the node; [`MergeSemantics`](/docs/api/platform/semantics) fuses a subtree; [`ExcludeSemantics`](/docs/api/platform/semantics)
hides one — all exercised in the runnable program above.

`Semantics::text_direction` sets the accessible label's reading direction
independently of visual layout. When labels merge, a phrase in the
opposing direction keeps its direction. For labels assembled directly
from multiple strings, use `incular::semantics::SemanticsLabelBuilder`.

For pronunciation metadata, pass an `AttributedString` to
`attributed_label`, `attributed_value`, or `attributed_hint`. Ranges use
UTF-16 code units. Replacing a field with its plain setter clears its spans.
The mobile bridge receives the metadata; native speech support is separate.



[`CheckedState`](/docs/api/platform/semantics): `Unchecked` (default) / `Checked` / `Indeterminate`;
`is_checked()`, `From<bool>`, displays `"false"` / `"true"` / `"mixed"`.

Related: [`Desktop`](/docs/api/platform/desktop).

Applications that inspect a window’s accessibility tree can keep an
`Application::ensure_semantics(window)` handle. Native screen-reader requests
and other handles remain independent, and effective transitions can be
observed with `on_semantics_enabled_changed`. Node updates arrive after layout.
