## KeyboardListener

```rust
use incular::prelude::*;

fn main() {
    let app = Application::new(|_cx| {
        Directionality::new(
            TextDirection::Ltr,
            Container::builder()
                .padding(EdgeInsets::all(24.0))
                .alignment(Alignment::CENTER)
                .child(
                    Column::builder()
                        .main_axis_size(MainAxisSize::Min)
                        .spacing(8.0)
                        .children(Vec::<Widget>::from([
                            KeyboardListener::new(Text::new("Type here"))
                                    .autofocus(true)
                                    .on_key_down(|event| {
                                        println!("down: {event:?}");
                                    })
                                    .on_key_up(|_event| {}).into(),
                            FocusableActionDetector::new(Text::new("Actions"))
                                    .on_focus_change(|has| {
                                        println!("focus: {has}");
                                    }).into(),
                        ]))
                        .build(),
                )
                .build(),
        )
        .into()
    })
    .expect("valid application");
    incular::run(app).expect("run application");
}
```

| Widget | Purpose |
| --- | --- |
| [`KeyboardListener`](/docs/api/input/keyboard) | Raw key phases with optional shortcuts wiring |
| [`ActionListener`](/docs/api/input/keyboard) | Listen to action Start/End phases (`on_action` fires on End) |
| [`CallbackShortcuts`](/docs/api/input/keyboard) | Bind activators directly to callbacks |
| [`FocusableActionDetector`](/docs/api/input/keyboard) | Focus + shortcuts + actions with highlight callbacks |

`on_key` runs first (`true` consumes); `with_shortcuts` wires a shortcuts +
actions pair; `focus_node` (alias `node`), `autofocus`, and
`include_semantics` (default true) configure focus and semantics.

## ActionListener

Listens to `Start`/`End` phases around a gesture [`Action`](/docs/api/state/action);
`on_action` fires on `End`, with `on_action_start` / `on_action_end` for the
individual phases.

## CallbackShortcuts

`Actions<C>` is the typed action registry keyed by [`CommandId`](/docs/api/input/keyboard);
[`ShortcutActivator`](/docs/api/input/keyboard) binds a trigger to an action id consumed by
[`CallbackShortcuts`](/docs/api/input/keyboard) (`shortcut(activator, callback)` /
`shortcuts([(activator, callback)])`) and [`FocusableActionDetector`](/docs/api/input/keyboard).

## FocusableActionDetector

`focus_node`, `enabled` (default true), `autofocus` (default false),
`shortcuts`/`actions` registries, and `on_focus_change` /
`on_show_focus_highlight` / `on_show_hover_highlight` — exercised in the
runnable program above.

`KeyboardEvent { key: KeyboardKey/NamedKey/Code, modifiers, state: KeyState }`
— see [`Desktop`](/docs/api/platform/desktop).

`Intent<C: CommandId>` wraps a typed command for the action registry
(`Intent::new`, `command()`). `ShortcutKey { code, modifiers }` (physical),
`LogicalShortcutKey { key, modifiers }` (logical), `SingleActivator {
trigger, modifiers, include_repeats }` (`new`, `with_repeats`, `accepts`),
[`ShortcutTrigger`](/docs/api/input/keyboard): `Down` (default) / `Press` / `Repeat` / `Up` / `Any`
(`matches(event)`). [`ActionInvocationPhase`](/docs/api/input/keyboard): `Start` / `End`;
[`ActionResult`](/docs/api/input/keyboard): `Handled` / `Ignored` (with `From<bool>`).

`LogicalKeySet::new(keys)` is Flutter's chord of logical keys, such as
Control plus S. Its `activator()` returns the equivalent `SingleActivator`
when the set has exactly one non-modifier key. A set converts into a
`ShortcutActivator`; a set that can never match becomes one that never fires.

## ShortcutRegistry

`ShortcutRegistry` holds application-wide shortcuts that widgets anywhere
below a `ShortcutRegistrar` add while they are mounted, such as menu
accelerators. `WidgetsApp` and `MaterialApp` include a registrar. Find the
registry with `ShortcutRegistry::maybe_of(context)`. A shortcut stays active
while its `ShortcutRegistryEntry` lives, and dropping the entry removes it.
`CharacterActivator` matches the character a key produces, which suits
layouts where the physical key differs.

```rust
use incular::prelude::*;

fn main() {
    let registry = ShortcutRegistry::new();
    let save = registry.add(CharacterActivator::new("s").control(true), || {
        println!("save")
    });
    let app = Application::new(move |_cx| {
        let _keep_registered = &save;
        Directionality::new(
            TextDirection::Ltr,
            ShortcutRegistrar::with_registry(registry.clone(), Text::new("Press Ctrl+S")),
        )
        .into()
    })
    .expect("valid application");
    incular::run(app).expect("run application");
}
```
