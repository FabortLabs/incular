# Rich keyboard content

The pinned services text-input :849 and widgets editable-text :877
registrations pair. The active attached client receives the
commit-content callback once. A mounted editor allowing GIFs receives
the original MIME type, exact nine bytes and unchanged content URI.
The text remains `test`; the runtime does not open a file, fetch the
URI or insert its string into the document.

Defaults match Flutter's seven accepted image MIME types when the app
enables content insertion, and no advertised types otherwise. A
custom allowlist cannot be empty. The runtime includes the allowlist
in native SetClient traits, rejects stale senders and blocked MIME
types, and distinguishes absent bytes from an empty byte array.
Four keyboard-content and four nearby private-command tests passed.
The scope is the mounted editor and Flutter-compatible channel; this
does not claim a change to the stock Android adapter or URI handling
by third-party keyboards.
