## Findings

Severity and category are as in the JSONL (`findings/gestures.jsonl`, 13 lines, schema-normalised, `status: pending-review`, `revalidated_at: a19bf487`). Each entry gives the scenario and divergence where one exists.

### gestures-001 — Singleton arena never resolves on pointer-down; first slop-crossing move is dropped under DragStartBehavior.start
**P1, behavior, confidence high.** Revalidated at HEAD: `sample_list_fling` diverges at frame 3 (48 ms), offset 40 vs 0; settled offsets stay 40 px apart (1193.7479 vs 1153.7479). Also explains `gestures__dismissible_threshold` (one 100 px move is dropped; no dismissal in Incular) and the early start in `gestures__draggable_drop_target`. Flutter closes the arena after pointer-down and a sole member wins (`gestures/binding.dart:526-532`, `gestures/arena.dart:251-276`). Incular's widget arena resolves only on acceptance by movement (`crates/incular-gestures/src/arena.rs:81-96`, `crates/incular-gestures/src/pointer.rs:635-665`). The `close` helper at `crates/incular-gestures/src/arena_member.rs:120` is used only for standalone recognizers. Fix: sole-member resolution on pointer-down with competition preserved when several members join.

### gestures-002 — Double-tap-only GestureDetector never fires onDoubleTap
**P1, behavior, confidence high.** `gestures__double_tap`, frame 5 (80 ms): Flutter count 1, Incular 0. Flutter tracks the first tap in `DoubleTapGestureRecognizer` (`gestures/multitap.dart:122-150, 257-263, 328-345`). Incular records `last_tap` only in the tap-up branch (`crates/incular-gestures/src/pointer.rs:763-782`), which needs onTap, onTapUp or onTapCancel. Fix: track the first tap independently.

### gestures-003 — onLongPress fires on release instead of at the 500 ms deadline
**P1, behavior, confidence high.** `gestures__long_press`, frame 33 (528 ms): Flutter count 1, Incular 0; onLongPressStart matches. Flutter calls onLongPress with onLongPressStart at the deadline (`gestures/long_press.dart:641-646, 737-748`). Incular's deadline poll returns only `LongPressStart` (`crates/incular-gestures/src/pointer.rs:291-312`); `LongPress` is emitted at pointer-up (`pointer.rs:700-738`, dispatched `:818-827`). Fix: dispatch onLongPress at the deadline.

### gestures-004 — Scale start and pinch values wait for the arena
**P1, behavior, confidence high.** `gestures__scale_single_pointer_pan`: scale start at 32 ms in Flutter, 48 ms in Incular (after the first move). `gestures__scale__two_pointer_pinch`: Flutter scale 1.5 at 48 ms and 1.8333 at 64 ms; Incular reports 1.0 at every frame, because its initial span is measured at late acceptance (`crates/incular-gestures/src/scale.rs:368`, arbitrated in `crates/incular-widgets/src/tree/interaction.rs:744-753`). Flutter starts a possible scale on acceptance (`gestures/scale.dart:806-815`). Fix: share the gestures-001 arena fix and measure the initial span from the contacts when the scale starts.

### gestures-005 — LongPressDraggable converts to an immediate Draggable and ignores the long-press delay
**P1, behavior, confidence high.** `gestures__long_press_draggable_quick_move`: 40 px move at 116 ms (before the 500 ms delay). Flutter never starts a drag; Incular starts at 132 ms. Flutter's delay is `kLongPressTimeout` with `DelayedMultiDragGestureRecognizer` (`widgets/drag_target.dart:404-445`). Incular's conversion builds a plain Draggable (`crates/incular-widgets/src/drag_drop.rs:580-600`). Fix: delayed-start mode on the drag source; feedback and callback parameters on the type.

### gestures-006 — ReorderableDelayedDragStartListener never starts a reorder when the deadline fires on a frame tick
**P0, behavior, confidence high for the failure; medium for the mechanism.**

Twin check (done as requested). Both sides use a 500 ms delay: Flutter `ReorderableDelayedDragStartListener` creates `DelayedMultiDragGestureRecognizer` with the default `kLongPressTimeout` (`widgets/reorderable_list.dart:1378-1394`, `gestures/multidrag.dart:574`); Incular uses `LONG_PRESS_TIMEOUT` through `on_long_press_start` (`crates/incular-gestures/src/constants.rs:28`, `crates/incular-widgets/src/scrolling/sliver_lists.rs:263-320`). Both use a touch pointer (Flutter `TestGesture` touch via `h.down`; Incular `Touch` in `harness/incular/src/lib.rs`). Same 16 ms frames, same fake clock, same rows (60 px, 3 items), same 600 ms hold.

Timeline (`gestures__reorderable_list_long_press`): mount 0 ms; frame 16 ms; touch down on row 0 at 16 ms; `pump(600)` records one frame at 616 ms, the 500 ms deadline inside the pump; move 150 px at 616 ms; two frames; up.

First divergence: frame 2 (616 ms), `reorder.started_index`: Flutter 0, Incular -1. Flutter then moves row 0 to y 150 at 632 ms, slides row 1 up, and fires `onReorderEnd(2)` at 664 ms. Incular never starts, so row 0 stays put and `ended_index` never fires.

Source: the delayed listener is a long-press `GestureDetector` wrapping the Draggable (`crates/incular-widgets/src/scrolling/sliver_lists.rs:263-320`). The Draggable's immediate recognizer joins the arena as non-simultaneous (`crates/incular-widgets/src/tree/interaction.rs:702`). Frame-driven timers fire through `pump_gesture_timers` (`interaction.rs:1352-1380`). Hypothesis: accepting the long press on a frame rejects the pending Draggable member, so the later move has no drag recognizer. The existing unit test `crates/incular-widgets/tests/reorderable.rs` (`delayed_listener_rejects_early_motion_and_starts_after_long_press`) passes because it fires the deadline on a Move event with no frame pump. It was run and passes (5 tests ok).

Impact: the common mobile reorder (long press on an item, then drag) does not reorder in a running app. Fix: make the delayed listener a single delayed drag recognizer; add a frame-driven reorder case to the unit tests.

Limitations: mechanism inferred, not instrumented. onReorder index convention not compared because no reorder completes.

### gestures-007 — GestureDetector has no secondary or tertiary tap or long-press callbacks
**P1, missing-feature, confidence high (API absence).** rg finds no secondary or tertiary tap, long-press or right-click handling in `crates/incular-gestures/src` or `crates/incular-widgets/src/gestures.rs`. Flutter's GestureDetector has 4 secondary tap, 4 secondary long-press, 3 tertiary tap and 7 tertiary long-press callbacks (`widgets/gesture_detector.dart`). Button bits exist (`crates/incular-core/src/input.rs:244-246`) but recognizers filter to the primary button. Source only; FrameHarness cannot send a right-click (harness request).

### gestures-008 — GestureDetector lacks onTapMove, onLongPressDown, onLongPressCancel and force-press callbacks
**P2, missing-feature, confidence high (API absence).** Flutter has `onTapMove` (`widgets/gesture_detector.dart:243`), `onLongPressDown` (`:255`), `onLongPressCancel` and the `onForcePress*` set. Incular's `gestures.rs` builders omit them. `ForcePressGestureRecognizer` (`crates/incular-gestures/src/force_press.rs:44`) is built nowhere in the widget layer. Source only.

### gestures-009 — Draggable feedback is never painted by the framework
**P1, missing-feature, confidence high (default differs by design).** The feedback builder is stored (`crates/incular-widgets/src/drag_drop.rs:141-160`) and exposed as a snapshot via `DragDropContext::feedback()` (`drag_drop.rs:20-40`). rg finds no consumer in crates or examples. Flutter paints feedback in an Overlay entry (`widgets/drag_target.dart`, `_DragAvatar`). The module docs say the app presents it (`drag_drop.rs:1-8`). Not visible in the trace (the recorder does not probe feedback); the pixel harness could confirm it, not run.

### gestures-010 — DragTarget rejecting a candidate gets no onLeave or onMove; nested targets do not fall through
**P2, lost-or-duplicate-callback, confidence high (source).** Flutter keeps rejected targets in `_enteredTargets`, so `didMove` and `didLeave` reach them (`widgets/drag_target.dart:776-790, 803-806`), and `updateDrag` continues to the next target in path order (`:905-947`; `_getDragTargets` at `:950-958`). Incular's `enter()` returns false without storing the target (`crates/incular-widgets/src/drag_drop.rs:519-530`), and `drag_target_ancestor` returns only the nearest target (`crates/incular-widgets/src/tree/interaction.rs:1785-1795`). Not scenario-tested.

### gestures-011 — DragTarget has no builder with candidate and rejected data
**P3, missing-feature (API), confidence high.** `DragTarget::new` takes a child only (`crates/incular-widgets/src/drag_drop.rs:447-500`). Flutter's builder receives candidate and rejected payloads. Depends partly on gestures-010.

### gestures-012 — Dismissible fling uses a fixed movement duration instead of Flutter's fling simulation
**P2, visible-motion, confidence medium-high (documented deviation).** `crates/incular-widgets/src/dismissible.rs` (module and widget docs) states the fling slides out over the remaining `movement_duration`. Flutter calls `_moveController.fling` (`widgets/dismissible.dart:531-539`), a spring simulation. Thresholds and final position match; motion does not. Not measured.

### gestures-013 — InteractiveViewer lacks trackpadScrollCausesScale; DeviceGestureSettings absent
**P3, missing-feature, confidence high (API absence).** Flutter's default `trackpadScrollCausesScale` is false (`widgets/interactive_viewer.dart:88`), so default behavior matches. The opt-in and `DeviceGestureSettings` slop overrides (`gestures/gesture_settings.dart:23`) have no Incular counterpart (rg). Trackpad input is not in the harness.

### gestures-014 — DiagonalDragBehavior lacks Flutter's weightedEvent/weightedContinuous distinction

- Severity: P3. Category: api (edge-case). Added by the orchestrator from the coverage sweep; status accepted.
- Flutter: `widgets/scrollable.dart:1795 (DiagonalDragBehavior: none, weightedEvent, weightedContinuous, free)`. Incular: `crates/incular-widgets/src/advanced_scrolling/two_dimensional.rs:117-125 (None, Free, Weighted)`.
- Evidence (source): Flutter has four values: weightedEvent locks the axis once per drag, weightedContinuous re-evaluates it on every update. Incular has a single Weighted value.
- Impact: Two-dimensional scroll views cannot reproduce one of Flutter's two weighted diagonal-drag behaviors; which one Weighted matches was not established.
- Cause: The two weighted modes were merged.
- Fix direction: Split Weighted into the two Flutter modes and document the default.
- Confidence: medium. Limitations: Source only; behavior of Incular's Weighted was not compared with either Flutter mode.
